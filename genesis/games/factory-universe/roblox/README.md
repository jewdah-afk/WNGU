## Honest status

**None of this Luau has been executed.** The build container could not
install Lune, Luau or Rojo binaries, and building Luau from source was also
blocked. The code follows the API patterns that already ship in
`cursed-survivors`:
- `AssetService:CreateEditableImage({ Size = ... })`
- `ImageLabel.ImageContent = Content.fromObject(ei)`
- `WritePixelsBuffer` with packed ABGR u32
- `Enum.ResamplerMode.Pixelated`
- `DataStoreService` under `pcall`

## First-run checklist

1. `rokit install` (pins: rojo 7.5.1, luau 0.740.0, lune 0.10.5).
2. **Parity first:** `lune run tests/parity`. Expected output:
   `terrain ok`, `26 checkpoints, 0 failures`, `parity OK`. If it
   diverges, the printed tick bisects the bug; fix `Sim.luau`, never the
   fixture.
3. `luau-analyze src` for type and syntax errors.
4. `rojo serve` and connect Studio. Enable **Mesh / Image APIs** in Game
   Settings (Security). Published games also need it in the Creator
   Dashboard.
5. Play solo. The perf line (bottom-left) shows fps, sim ms, compose,
   sprite and upload ms, tick lag and the desync count.
6. Start a 2-player local server and build on both clients. The desync
   count must stay at 0.

## Networking

The server stamps every accepted command with `applyTick = tick + 6` and
broadcasts it before reaching that tick. Clients run the same sim and may
simulate up to `lastClock + DELAY - 1`. A state hash rides the clock every
300 ticks; a mismatch triggers a snapshot resync. Bandwidth is one message
per player action plus a 10 Hz clock, whatever the factory size.

## Known gaps

- No sound: Roblox needs uploaded audio assets, and none have been created.
- Water is static: animated frames exist in the atlas, but no redraw pass
  uses them yet.
- No gamepad bindings.
- Zoom recreates the EditableImage. Only three sizes are allowed, to stay
  within the image budget.
